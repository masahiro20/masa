# COMPASS Meet — セキュリティ面の対策と、残っている課題

最終更新：2026-11-17（このリポジトリのコミット `0347f93` 時点）
仕組みの全体は同じフォルダの「仕組み.md」を参照。

この文書は、ほかの人（またはほかの AI）に「この状態で問題ないか」を確かめてもらうために書いた。**できていること**と**できていないこと・弱いところ**を分けて、隠さずに書く。

---

## 1. 前提

- 用途：注文住宅の営業担当とお客様（個人）の打ち合わせ。図面・資料の画面共有を伴う
- 段階：社内テスト。お客様との本番利用はまだしていない
- 扱う個人情報：参加者の表示名（お客様のお名前が入りうる）、件名（例「山田様 間取りのご相談」）、チャットの文、通話中の映像・音声
- 運用者：営業担当 1 名（技術者ではない）。サーバーの常時監視はしていない

## 2. できている対策

### 通信の暗号化
- サイトとの通信はすべて HTTPS（Vercel。HSTS あり）
- 映像・音声は WebRTC の決まりで DTLS-SRTP による暗号化が必ずかかる。端末どうしで直接やりとりし、**サーバー（Vercel・Upstash）には映像・音声が届かない**
- 録画・録音の機能はない

### 通話に入れる人を絞る
- 通話リンクの ID は `abc-defg-hij` 形式。24 文字×10 桁＝約 6.3×10¹³ 通り、`crypto.randomBytes` で生成。総当たりで見つけるのは現実的でない
  - 細かい点：`バイト % 24` で文字を選んでいるため、わずかな偏りがある（256 は 24 で割り切れない）。実害は小さいと判断
- **待合室**：中に人がいるときに来た人は「待機中」になり、中の人が「許可」するまで映像・音声・チャットに一切触れられない（合図の中継・チャット・状態送信は、入室済みでなければサーバーが 403 で断る）
- 参加者ごとに 128 ビットのランダムな合言葉を発行し、以後の操作はすべて参加者 ID ＋ 合言葉で本人確認する
  - 比較は `crypto.timingSafeEqual`（時間差で推測されないように）
  - 受け取りのポーリング（GET）では、合言葉を**アドレスではなく `X-Peer-Secret` ヘッダー**で送る。アドレスに載せると Vercel のアクセス記録に残るため。アドレスに載せた合言葉は受け付けない（試験で確認）
- 断られた人は「拒否」状態になり、以後の操作はすべて断られる。30 秒で片付く

### 管理操作
- ルームの削除（と、設定すれば発行も）は管理用 API キーが必要
- **API キーが設定されていないときは、管理操作をすべて断る**（以前は「キー未設定なら誰でも可」だったのを修正済み）
- 本番には 32 文字のランダムなキーを Vercel の環境変数（暗号化）に設定済み。リポジトリには入っていない

### 画面まわり（ブラウザ側の攻撃対策）
- 名前・チャットなど人が入力した文字は、すべて `textContent` で表示（HTML として解釈しない）→ 文字の埋め込みによる攻撃（XSS）を防ぐ
- Content-Security-Policy を設定：
  `default-src 'self'; script-src 'self'; style-src 'self' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data: blob:; media-src 'self' blob:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'; object-src 'none'`
  - ページ内に直接書いたスクリプトはなくした（外部・埋め込みスクリプトは動かない）
  - `frame-ancestors 'none'` と `X-Frame-Options: DENY` で、他のサイトの中に埋め込んで操作させる攻撃（クリックジャッキング）を防ぐ
- `Referrer-Policy: no-referrer`：通話ページから外部リンクを開いても、通話のアドレスが相手に渡らない
- `Permissions-Policy`：カメラ・マイク・画面共有は自サイトだけ、位置情報は使わない
- `X-Content-Type-Options: nosniff`
- 入力の長さ制限（名前 40 字、件名 80 字、チャット 1000 字など）

### データを残さない
- 合図・チャットは受け取った時点で Upstash から消える（最長でも 6 時間で自動消去）
- 参加者情報は退出時、または 30 秒無通信で消える
- ルーム情報（件名・日時）は 30 日で自動消去
- 映像・音声はどこにも保存されない

### そのほか
- 外部の npm パッケージを一切使っていない（Node.js 標準の機能だけ）→ 部品経由で悪いコードが入り込む心配が小さい
- Vercel のプレビュー版（本番以外）は Vercel のログインが必要。本番の URL だけが誰でも開ける
- 秘密の値（Upstash のトークン・API キー）は Vercel の環境変数だけにあり、公開リポジトリには入っていない

## 3. できていないこと・弱いところ（確認してほしい点）

重要度は筆者の見立て。

### 高
1. **担当者（主催者）の本人確認がない**
   - 「最初に入った人がそのまま入室し、後から来た人を許可できる」仕組み。社員のログインはない
   - お客様が担当者より先に入ると、お客様が担当者を許可する側になる
   - リンクが第三者に漏れ、その人が最初に入ると、その人が許可役になれる
   - **入室済みの人なら誰でも**許可・拒否ができる（主催者だけ、になっていない）
   - 対策案：社員だけが持つ「主催者用リンク（別の合言葉付き）」を発行し、許可は主催者だけにする。または COMPASS のログインと連携する
2. **リンクの発行に制限がない（`PUBLIC_CREATE` が既定で有効）**
   - 誰でもルームを作れる。大量に作られると Upstash の無料枠を使い切り、全体が止まる（サービス妨害）
   - 回数制限（レート制限）もない。参加申し込み・ポーリングにも回数制限なし
   - 対策案：COMPASS とつないだら `PUBLIC_CREATE=0`（API キー必須）にする。それまでは社内でだけリンクを作る運用。Vercel のファイアウォールでの回数制限も検討
3. **Vercel の Hobby（無料）プランは個人・非商用向けの規約**
   - お客様との業務利用に使うと規約に反するおそれ。本番前に有料プランか別の置き場所へ

### 中
4. **TURN サーバーがない**：一部のネットワークではつながらない（安全性ではなく使い勝手の問題だが、つながらないときにお客様が LINE 通話などに流れる運用リスクがある）。入れる場合は TURN の認証情報を期限付きで発行する仕組みが要る
5. **参加者どうしに IP アドレスが見える**：端末どうしで直接つなぐ方式（P2P）の性質上、接続候補（ICE）に互いの IP アドレスが含まれ、相手のブラウザに渡る。また、STUN に Google の公開サーバーを使うため、Google にも参加者の IP アドレスが届く
6. **個人情報が外部サービスを通る**：表示名・件名・チャット・接続情報（IP アドレスを含む）が、一時的に Upstash（米国企業。保存場所は作成時に選んだ地域）と Vercel（米国企業）を通る。社内の個人情報の取り扱い方針・お客様への説明と合っているかの確認が必要
7. **ルーム情報は ID を知っていれば誰でも読める**：`GET /api/rooms/:id` で件名・日時・参加人数が見える。件名に詳しい個人情報（住所など）を入れない運用が必要
8. **リンクは 30 日間何度でも使える**：打ち合わせが終わっても無効にならない（削除 API はあるが、画面からは消せない）。終了後の自動無効化や「部屋を閉じる」ボタンがない
9. **公開リポジトリ**：ソースコードが誰でも読める。秘密の値は入っていないが、仕組みの弱点を探しやすくはなる

### 低
10. 通話中の参加者の追い出し（キック）機能がない（入室を許可した後に外す方法がない）
11. 監視・通知がない（不審な大量アクセスがあっても気づけない）。Vercel のログは Hobby プランだと 1 時間しか残らない
12. 表示名は自己申告。なりすまし（「ホームランディック 中谷」と名乗るなど）を防げない
13. チャットの文はサーバー（Upstash）を通る時点では暗号化されていない（HTTPS で運ばれ、読まれたら消えるが、置かれている間は平文）

## 4. 確かめたこと

- 自動試験（`meet/tests/server.test.js`、10 件すべて合格）で確認した安全面の動き：
  - 許可前の人は中継・チャットができない（403）
  - 合言葉が違うと操作できない／アドレスに載せた合言葉は受け付けない
  - 断られた人は以後何もできない
  - API キー未設定でも削除はできない／キーなしの削除は断る
  - ページに CSP・X-Frame-Options・Referrer-Policy が付く
- ブラウザ 2 台の試験（`meet/tests/e2e.js`）で、CSP を付けた状態でも通話・画面共有・チャットが動くことを確認
- 本番で Upstash に接続していること、エラーログがないことを確認

## 5. 本番利用（お客様との打ち合わせ）までにやるべきこと（筆者の提案）

1. 主催者の本人確認（上の 3-1）
2. 発行を API キー必須にする、または回数制限を入れる（3-2）
3. Vercel の有料プラン、または別の置き場所への移行（3-3）
4. TURN の用意（3-4）
5. 個人情報の取り扱いを社内方針と照らし合わせる（3-5、3-6）
