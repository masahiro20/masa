# COMPASS Meet — 動作の仕組み

最終更新：2026-11-18（ローカルのコミット `db9640d` 以降。本番は未反映）

## 1. 何をするものか
ホームランディックの営業担当が、お客様とオンラインで商談するためのブラウザ通話ツールです。COMPASS の予定から使うことを想定しています。お客様はアカウント登録なしで、リンクを開くだけで参加できます。担当者はログインして主催者になり、入室の許可、図面への書き込み、メモ、記録までを行います。

## 2. 全体の構成

```
 [ブラウザ A] ── 映像・音声・書き込み（WebRTC・暗号化・端末どうしで直接）── [ブラウザ B]
      │  ↑ つながらないときは TURN（中継サーバー、未契約）を経由
      │ HTTPS（受付・合図・記録）
      ▼
 Vercel（東京 hnd1）
   静的ファイル：index.html / room.html / records.html / *.js / style.css
   関数：api/handler.js → lib/api.js（受付・権限）
              ├ lib/auth.js（スタッフの本人確認）
              ├ lib/ratelimit.js（回数制限）
              ├ lib/secure.js（暗号化・署名・ハッシュ）
              ├ lib/turn.js（TURN の期限付き資格情報）
              └ lib/ai.js（AI 議事録。初期状態は無効）
      │ HTTPS（REST）
      ▼
 Upstash Redis（合図の受け箱・参加者表・暗号化した記録）
```

依存パッケージはありません（Node.js 22 の標準機能のみ）。手元で動かす場合は、`server.js` が同じ `lib/api.js` を使います。

## 3. 役割
| 役割 | なり方 | できること |
|---|---|---|
| 主催者（担当） | スタッフとしてログインしたルームの持ち主・管理者、または主催者用リンクの合札を持つ人 | すべて（入室の許可、強制退出、権限設定、締切、終了、メモ、記録、文字起こしの依頼） |
| 参加者（お客様） | お客様用リンクを開いて名前を入れる（＋任意の確認コード） | 主催者の許可後に映像・音声・チャット。画面共有・書き込みは許可された範囲で |

## 4. 打ち合わせの流れ
1. **作成**：担当者がログインし、件名・お客様名（記録用）・顧客 ID・日時・確認コードの有無を入れて作成します（`POST /api/rooms`）。返ってくるのは、お客様用リンク、主催者用リンク（`#host=` 付き）、確認コード（その場で 1 回だけ表示）、有効期限です。
2. **お客様が開く**：入室前の画面には、日時と担当者名だけが出ます。カメラ・マイクの確認（音量の表示、機器の切り替え）をしてから参加します。
3. **待合室**：お客様は必ず待合室に入ります。担当者がいなければ「担当者はまだ入室していません」と表示されます。
4. **担当者が入室**：待っている人の一覧が届くので、「許可」か「お断り」を選びます。
5. **接続**：新しく入った人が、先にいる全員に offer を送ります。answer を受け取り、ICE 候補を 150 ミリ秒ごとにまとめて送り、端末どうしが直接つながります。音声・映像の枠とデータチャネル（`negotiated: true, id: 0`）は最初から作っておき、カメラ⇔画面共有は枠の中身を差し替えるだけです。
6. **通話中**：画面共有と書き込み、ホワイトボード、チャット、リアクション・挙手、参加者一覧、担当者のメモ（自動保存）、回線状態の表示を使えます。
7. **終了**：担当者の「全員の通話を終了」で全員に知らせ、リンクは使えなくなります。メモ・保存したチャット・出入りの記録は「打ち合わせ記録」で見返せます。

## 5. 合図の受け渡し（シグナリング）
- Vercel の関数は状態を持てないため、サーバー→ブラウザの通知は「ブラウザが取りに行く」方式です。取りに行く間隔は、つなぎ始めとやりとりの直後は 0.6 秒、接続待ちは 0.8 秒、静かなときは 2.5 秒、待合室では 1.2 秒です。
- 合図は Upstash の受け箱（リスト）に積み、取りに来たときに「読むと同時に消す」（MULTI/EXEC）ようにしています。
- 取りに来る応答には、自分あての出来事・自分の状態が入ります。入室済みの人には参加者一覧も入ります。

## 6. 再接続
- 接続が `failed` になったとき、または `disconnected` が 4 秒続いたときは、ICE をやり直します（最初に offer を出した側がやり直し、もう一方は依頼を送る）。やり直す前に、TURN の資格情報も取り直します。
- ブラウザの `online` 通知（Wi-Fi⇔モバイル回線の切り替えなど）でも、全員とつなぎ直します。
- **ページを開き直した場合**は、合言葉をタブの中（sessionStorage）に残しているので、そのまま通話に戻れます。戻った側が全員に「resync」を送ってから、改めて offer を出します。
- 45 秒取りに来なかった人は抜けたとみなし、ほかの人に知らせます。

## 7. 回線状態の表示
3 秒ごとに `getStats()` で往復時間と取りこぼし率を見て、映像ごとに 3 段階で表示します。画面右上には全体の状態を出します（「回線 良好／やや不安定／不安定」）。中継サーバーを経由しているかどうかも、マウスを重ねると分かります。

## 8. 書き込み（画面共有・ホワイトボード）
- **映像そのものには書き込みません。** 映像の上に透明なキャンバスを重ねます。
- 座標は「共有されている映像の枠（黒帯を除いた部分）」に対する 0〜1 の割合で持ちます。画面の大きさ・向き・解像度が人によって違っても、同じ場所に表示されます（大きさの違う 3 台で一致を確認済み）。
- ホワイトボードは、縦横比 1.6 の「紙」、または下敷き画像（図面）の縦横比を基準にします。
- ペンは書いている途中も 40 ミリ秒ごとに点を送るので、相手の画面にもほぼリアルタイムで出ます。
- 道具：ペン、矢印、四角、丸、文字、付箋・移動（ホワイトボードのみ）、消しゴム、元に戻す（自分の最後の書き込み）、消去（主催者は全員分、お客様は自分の分）、色 6 色、太さ 3 段階、画像の貼り付け（長辺 1600px の JPEG にしてから送る）、下敷き（図面）、画像として保存（画面共有は映像の 1 コマと重ねて PNG）。
- 書いた人の名前を書いた直後に 4.5 秒表示し、書いた人の一覧も道具の欄に出します。
- 後から入った人には、主催者がいまの状態（画像を含む）をまとめて送ります。
- **既知の限界**：共有している側がスクロールしたりウィンドウの大きさを変えたりすると、中身だけが動いて書き込みは残ります。共有している人や共有の中身が変わったときは、書き込みを自動で消します。図面に書き込む場合は、ホワイトボードに図面を下敷きとして読み込む方法を推奨します（全員が同じ紙に書くので、ずれません）。

## 9. 保存するもの（Redis のキー）
| キー | 中身 | 期限 |
|---|---|---|
| `room:<ID>` | ルーム（持ち主、日時、期限、主催者合札のハッシュ、確認コードのハッシュ、権限、記録の状態、**件名などは暗号化**） | リンクの期限＋7 日 |
| `ended:<ID>` / `lock:<ID>` | 終了の印 / 締切の印 | 同上 |
| `peers:<ID>` / `seen:<ID>` | 参加者（名前・役割・合言葉のハッシュ・状態）/ 最後に取りに来た時刻 | 退出・45 秒の無通信で削除 |
| `inbox:<ID>:<参加者>` | その人あての合図・出来事 | 読んだら消える。最長 6 時間 |
| `mtg:<ID>` | 会議記録（件名・お客様名・顧客／案件／予定 ID・メモ・議事録・ホワイトボード）**暗号化** | 180 日 |
| `mtg:<ID>:log` / `:chat` / `:chatdel` / `:tr` | 出入り・保存したチャット・削除印・文字起こし（各行を**暗号化**） | 180 日 |
| `staffidx:<社員ID>` | その人の会議の一覧 | 180 日 |
| `rl:*` / `revoked:*` / `jti:*` | 回数制限 / ログアウト済み合札 / 使用済み JWT | 数分〜12 時間 |

Upstash は長期保存の置き場所としては最適ではありません。COMPASS と連携した後は、会議記録を COMPASS 側か、長期保存に向いたデータベース（例：Postgres）に移す想定です。データの形（顧客 ID・案件 ID・予定 ID でのひも付け）はそのために用意しています。

## 10. API
| 呼び方 | 用途 | 認証 |
|---|---|---|
| `POST /api/auth/login` / `logout`、`GET /api/auth/me` | 暫定ログイン | 同じサイトからのみ |
| `GET /api/auth/google/start` / `callback` | 会社の Google アカウントでのログイン（OpenID Connect・PKCE） | Google |
| `POST /api/auth/compass` | COMPASS の JWT を Cookie に交換 | JWT |
| `POST /api/rooms`、`GET /api/rooms` | 作成・自分の一覧 | スタッフ |
| `GET /api/rooms/:id` | 入室前の最低限の情報 | なし（回数制限あり） |
| `GET /api/rooms/:id/detail`、`DELETE /api/rooms/:id` | 詳細・取り消し | 持ち主／管理者 |
| `POST /api/rooms/:id/join` | 入室の申し込み | なし（主催者はスタッフか合札） |
| `GET /api/rooms/:id/poll`、`/ice` | 出来事の受け取り・TURN 資格情報 | 参加者（`X-Peer-Secret`） |
| `POST /api/rooms/:id/{signal,chat,chat-delete,state,react,hand,rec-consent,transcript,leave}` | 参加者の操作 | 参加者 |
| `POST /api/rooms/:id/{admit,deny,kick,mute,stop-share,perms,lock,end,rec-request,rec-stop}` | 主催者の操作 | 主催者 |
| `GET /api/meetings`、`GET/DELETE /api/meetings/:id`、`PUT .../notes`、`PUT .../minutes`、`PUT .../board`、`GET .../export`、`POST .../summarize` | 会議記録 | 持ち主（閲覧・削除は管理者も） |

## 11. 設定（環境変数）
| 変数 | 意味 | 必須 |
|---|---|---|
| `DATA_KEY` / `SESSION_SECRET` | 保存データの暗号化鍵 / ログインの署名鍵（`node scripts/setup.js keys` で作る） | 本番で必須 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_ALLOWED_DOMAIN` / `GOOGLE_ADMIN_EMAILS` | 会社の Google アカウントでのログイン（手順は「Googleログインの設定手順.md」） | 推奨 |
| `STAFF_ACCOUNTS` | 社員アカウント（`node scripts/setup.js staff` で 1 件ずつ作る。Google ログインを使うなら不要） | 任意 |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | Upstash（Vercel の Storage から追加すると自動で入る） | Vercel で必須 |
| `MEET_API_KEY` | COMPASS のサーバーから呼ぶ鍵 | 任意 |
| `COMPASS_JWT_SECRET` | COMPASS の JWT を確かめる鍵 | COMPASS 連携時 |
| `TURN_PROVIDER` ＋ `TURN_SECRET`・`TURN_URLS`、または `CF_TURN_KEY_ID`・`CF_TURN_API_TOKEN` | TURN | 契約後 |
| `MAX_PEERS`（6）、`MEETING_RETENTION_DAYS`（180）、`PUBLIC_URL` | 上限・保持期間・リンクの頭 | 任意 |
| `TRANSCRIBE_PROVIDER=webspeech` ＋ `TRANSCRIBE_EXTERNAL_APPROVED=1` | 文字起こし（ブラウザの音声認識。Chrome は音声を Google に送るため承認が必要） | 承認後 |
| `AI_PROVIDER=anthropic` ＋ `ANTHROPIC_API_KEY` ＋ `AI_EXTERNAL_APPROVED=1` | AI 議事録 | 承認後 |

## 12. 試験
- `npm test`：API と部品の試験 47 件（権限・不正操作・暗号化・回数制限・同意の流れ・TURN・AI の検証）
- `node tests/e2e.js`：Chromium 3 台（偽のカメラ）で、ログイン、作成、待合室、許可、3 人での通話、画面共有への書き込み（画面の大きさ違いで位置が一致）、ホワイトボード、チャット、メモ、開き直し、全員ミュート、強制退出、終了、記録まで確認します。`E2E_MODE=vercel` で Vercel の入口を通した形でも確認済みです。
