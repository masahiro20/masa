エンジニアのポートフォリオは、**「目的のある作品を作る」→「コードをGitHubで公開し、READMEで説明する」→「作品をまとめたポートフォリオサイトを用意する」**という流れで作るのが基本です。未経験者の場合、作品の数や派手さよりも、**なぜそれを作り、どう考えて実装したかを説明できること**が大切です。

この記事では、未経験からエンジニア転職を目指す人向けに、ポートフォリオの作り方を7つのステップで整理します。GitHubの公式ドキュメントをもとに、READMEに書く内容や、GitHub Pagesでポートフォリオサイトを公開する手順も紹介します。

:::summary この記事で分かること

- 未経験者がポートフォリオを作る7つのステップ
- READMEの書き方と、GitHub Pagesでサイトを公開する手順
- 転職活動でポートフォリオを見せるときのポイント
:::

## エンジニアのポートフォリオに含めたい3つの要素

エンジニアのポートフォリオは、主に次の3つで構成されます。

| 要素 | 内容 | 役割 |
| --- | --- | --- |
| 作品（アプリ・サイト） | 実際に動かせる成果物 | 何を作れるかを示す |
| ソースコードとREADME | GitHubなどで公開したコードと説明 | どう作ったか、どう考えたかを示す |
| ポートフォリオサイト | 自己紹介と作品の一覧をまとめたページ | 全体を短時間で見てもらう入口になる |

**採用担当者がすべてのコードを読むとは限らないため、作品の概要がひと目で分かる入口を用意しておく**と、見てもらいやすくなります。

## 未経験者がポートフォリオを作る7ステップ

:::steps ポートフォリオの作り方
1. **応募したい職種を決める**：Webエンジニア、インフラエンジニアなど、目指す職種によって見せたい作品が変わります。
2. **作品のテーマを決める**：自分や身近な人の困りごとを解決するなど、目的が説明できるテーマを選びます。
3. **使う技術を選ぶ**：応募したい求人でよく使われている言語やフレームワークを選びます。
4. **小さく作って動かす**：最初は必要な機能を絞り、まず動く形にしてから機能を足します。
5. **GitHubでコードを公開する**：コードをリポジトリにまとめ、READMEで作品を説明します。
6. **ポートフォリオサイトを作る**：自己紹介、作品の一覧、各作品へのリンクをまとめます。
7. **見直して改善する**：第三者に見てもらい、分かりにくい点を直します。
:::

### ステップ1・2：職種とテーマを決める

ポートフォリオは、応募先に「入社後に活躍できそうか」を判断してもらう材料です。**目指す職種が決まると、どんな作品を作ればよいかが見えてきます**。たとえばWebエンジニアを目指すなら、ユーザーが使うWebアプリを作り、データの登録や表示などの基本的な機能を実装するのが分かりやすい例です。

テーマは、自分の前職の経験や日常の困りごとから考えると、作った理由を自分の言葉で説明しやすくなります。職種ごとの違いは {{link:it-engineer-shokushu-shurui-chigai|ITエンジニアの職種の種類と違い}} で整理しています。

### ステップ3・4：技術を選んで小さく作る

使う技術は、応募したい求人の募集要項を見て選ぶのが確実です。**最初から多くの機能を詰め込むと、完成しないまま時間が過ぎてしまう**ことがあるため、まずは必要最小限の機能で動く形を目指し、そこから改善していきましょう。

:::warning 教材の作品をそのまま載せない
学習教材で作った作品をそのまま載せると、他の応募者と同じ内容になり、自分の考えが伝わりにくくなります。教材で学んだ技術を使いつつ、テーマや機能を自分で考えた作品を用意しましょう。評価されにくいポートフォリオの特徴は {{link:mikeiken-portfolio-hyoukasarenai-riyuu|未経験のポートフォリオが評価されない理由}} で詳しく解説しています。
:::

## GitHubでコードを公開し、READMEで説明する

作品のコードは、GitHubのリポジトリにまとめて公開するのが一般的です。GitHubの公式ドキュメントでは、READMEファイルについて、**プロジェクトがなぜ有益なのか、何ができるか、どのように使えるかを他者に伝えるためのもの**と説明しています。また、READMEは多くの場合、リポジトリへの訪問者が最初に目にするものだとしています。

同ドキュメントでは、READMEに通常含まれる情報として、次のような項目が挙げられています。

- このプロジェクトが行うこと
- このプロジェクトが有益な理由
- このプロジェクトの使い始め方
- このプロジェクトに関するヘルプをどこで得るか
- このプロジェクトのメンテナンス者とコントリビューター

ポートフォリオのREADMEでは、これに加えて次の点も書いておくと、考えが伝わりやすくなります。

:::check ポートフォリオのREADMEに書きたいこと
- 作品の概要と、作ろうと思った理由
- 主な機能と、画面のイメージ
- 使った言語・フレームワーク・ツールと、選んだ理由
- 工夫した点、苦労した点と解決の方法
- 今後追加したい機能や、改善したい点
:::

**「工夫した点」と「今後の改善点」を書いておくと、面接で深掘りされたときの話の材料にもなります**。

## GitHub Pagesでポートフォリオサイトを公開する手順

ポートフォリオサイトは、GitHub Pagesを使って公開する方法があります。GitHubの公式ドキュメントでは、GitHub Pagesは履歴書の共有などにも使えると紹介されており、ユーザーサイトを作る手順は次のように案内されています。

1. 新しいリポジトリを作成し、リポジトリ名を「ユーザー名.github.io」にする
2. 可視性を選び、READMEの追加をオンにしてリポジトリを作成する
3. リポジトリの「Settings」から「Pages」を開く
4. 「ビルドとデプロイ」の「ソース」で「ブランチからのデプロイ」を選び、公開元のブランチを選ぶ
5. 「ユーザー名.github.io」にアクセスしてサイトを確認する

同ドキュメントによると、変更をプッシュした後、サイトへの変更が反映されるまでに最大10分かかる場合があります。また、GitHub Pagesを使えるかどうかは、リポジトリの公開範囲や利用しているGitHubのプランによって異なると案内されているため、事前に確認しておきましょう。

WordPressでポートフォリオサイトを作る方法は {{link:wordpress-portfolio-tsukurikata-mikeiken|WordPressでポートフォリオの作り方}} で解説しています。

:::point ポートフォリオサイトに載せたいページ
- 自己紹介（経歴、エンジニアを目指す理由、学習してきたこと）
- 作品の一覧（概要、使った技術、作品とGitHubへのリンク）
- 連絡先や、職務経歴書とあわせて見てほしい情報
:::

## 自分で作るか、講座で学びながら作るか

ポートフォリオの作り方には、独学で作る方法と、講座で学びながら作る方法があります。

:::merit 独学で作るメリット
- 費用を抑えられる
- テーマや技術を自由に選べる
- 調べて解決する力が身につきやすい
:::

:::demerit 独学で作るデメリット
- つまずいたときに相談できる相手がいない
- 作品の完成度を客観的に判断しにくい
- 完成までに時間がかかることがある
:::

基礎がまだ不安な人は、{{aff:learning-online-course|オンライン動画講座}}で必要な技術を学びながら作品を作る方法もあります。動画を見ながら手を動かせるため、環境構築などでつまずきやすい初心者でも進めやすくなります。

## 転職活動でポートフォリオを見せるときのポイント

ポートフォリオは、履歴書や職務経歴書とあわせて応募先に提出したり、面接で説明したりする場面があります。作品のURLやGitHubのリンクが正しく開けるか、応募前に必ず確認しておきましょう。スマートフォンから開いたときの表示や、ログインが必要な作品なら試用できるアカウントの案内があるかも、あわせて見直しておくと安心です。

面接では、作品について「なぜこの技術を選んだのか」「一番苦労したところは」などを聞かれることがあります。**READMEに書いた内容を、自分の言葉で説明できるように準備しておく**と安心です。

自分の作品が応募先の求めるレベルに合っているか分からない場合は、{{aff:career-it-agent|IT・Web業界に特化した転職エージェント}}に相談すると、応募先に合わせた見せ方のアドバイスを受けられることがあります。

## よくある質問

### 未経験エンジニアのポートフォリオの作り方は？

目指す職種を決め、目的が説明できるテーマで作品を作り、GitHubでコードを公開してREADMEで説明するのが基本です。そのうえで、自己紹介と作品の一覧をまとめたポートフォリオサイトを用意すると、全体を見てもらいやすくなります。

### Webエンジニアのポートフォリオは何を作ればいい？

ユーザーが使うWebアプリを作り、データの登録や表示などの基本的な機能を実装するのが分かりやすい例です。応募したい求人で使われている言語やフレームワークを選ぶと、入社後の活躍をイメージしてもらいやすくなります。

### ポートフォリオサイトの作り方は？

GitHub Pagesを使う方法や、WordPressを使う方法があります。GitHub Pagesでは、「ユーザー名.github.io」という名前のリポジトリを作り、Settingsの「Pages」から公開元のブランチを選ぶことで、ユーザーサイトを公開できます。

### ポートフォリオのREADMEには何を書く？

GitHubの公式ドキュメントでは、プロジェクトが行うこと、有益な理由、使い始め方などが一般的な内容として挙げられています。ポートフォリオでは、作った理由、使った技術と選んだ理由、工夫した点、今後の改善点も書いておくと考えが伝わりやすくなります。
