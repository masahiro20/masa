求人を見ていると、フロントエンドの募集にReactという言葉がよく出てくる。勉強してみようと思ったものの、JavaScriptもまだ自信がなく、何から手をつければいいのか分からない。そんな場面を想定して書きました。新しい技術の名前が次々に出てくると、置いていかれるような気持ちになるものです。

Reactの勉強方法は、**JavaScriptの基礎を確認したうえで、React公式ドキュメント（日本語版）の「クイックスタート」から順に進め、小さなアプリを自分で作る**、という流れが取り組みやすい方法です。公式ドキュメントのクイックスタートでは、日々の開発で使うReactのコンセプトのうち80％の部分を紹介すると説明されています。

また、公式ドキュメントのほとんどのページには、ブラウザ上で直接コードを編集できるサンドボックスが含まれており、**Reactを試すために何かをインストールする必要はない**と案内されています。まずは手元の環境を整える前に、ブラウザで触ってみるところから始められます。

## Reactを始める前に確認したいこと

ReactのコンポーネントはJavaScriptの関数として書かれます。公式ドキュメントのクイックスタートでも、Reactにおけるコンポーネントとは**マークアップを返すJavaScript関数**だと説明されています。そのため、JavaScriptの基礎が分からないままReactに進むと、どこからがReactでどこからがJavaScriptなのかが分からなくなりがちです。

:::check Reactの前に確認したいJavaScriptの基礎
- 変数、条件分岐、繰り返しが書ける
- 関数を定義して呼び出せる
- 配列とオブジェクトを扱える
- importとexportでファイルを分ける考え方が分かる
- HTMLとCSSの基本的な書き方が分かる
:::

公式ドキュメントでも、JavaScriptの構文で分からない部分があればMDNやjavascript.infoのリファレンスを参照するよう案内されています。**全部を完璧にしてから進む必要はありませんが、関数と配列の扱いだけは先に慣れておく**と、Reactの理解がぐっと楽になります。

HTML・CSS・JavaScriptを学ぶ順番は {{link:html-css-javascript-dokugaku|HTML・CSS・JavaScriptを独学する順番は？}}、JavaScriptでつまずきやすいところは {{link:javascript-dokugaku-muzukashii|JavaScriptの独学が難しいと感じる理由は？}} で整理しています。

## React公式ドキュメントの構成

React公式ドキュメント（日本語版）の「Learn」は、大きく次のように構成されています（2026年11月時点）。

| 区分 | 主な内容 |
| --- | --- |
| スタートガイド | クイックスタート、チュートリアル（三目並べ）、Reactの流儀、インストール、セットアップ |
| UIの記述 | 初めてのコンポーネント、JSX、propsの受け渡し、条件付きレンダー、リストのレンダー |
| インタラクティビティの追加 | イベントへの応答、state（コンポーネントのメモリ）、stateの更新 |
| stateの管理 | stateの共有、stateの保持とリセット、リデューサ、コンテクスト |
| 避難ハッチ | ref、エフェクト、カスタムフック |

結局のところ、初心者は**「スタートガイド」→「UIの記述」→「インタラクティビティの追加」までを一つの区切り**と考えると進めやすくなります。「stateの管理」や「避難ハッチ」は、小さなアプリを作ってみてから読むほうが、なぜその仕組みが必要なのかを理解しやすくなります。

## 初心者が学ぶ順番：5つのステップ

:::steps Reactの勉強の進め方
1. **クイックスタートを読む**：コンポーネントの作成、マークアップとスタイル、データの表示、条件分岐とリスト、イベントと画面の更新、コンポーネント間のデータの共有を一通り見ます。
2. **チュートリアルで手を動かす**：公式の三目並べのチュートリアルで、実際に動くものを作りながら基本を確かめます。
3. **「UIの記述」を読み進める**：JSXやprops、リストのレンダーなど、画面を組み立てる考え方を深めます。
4. **「インタラクティビティの追加」でstateを学ぶ**：ボタンを押すと表示が変わるなど、画面が動く仕組みを理解します。
5. **小さなアプリを自分で作る**：学んだことを組み合わせて、自分で決めたアプリを作ります。
:::

**ステップ1〜4は、読むだけでなくサンドボックスのコードを自分で書き換えてみる**ことが大切です。少し変えて結果がどう変わるかを見るだけでも、理解が深まります。

### JSXでつまずきやすいところ

公式ドキュメントでは、JSXはHTMLより構文が厳格で、`<br />` のようにタグを閉じる必要があること、コンポーネントは複数のJSXタグをそのまま返せず、共通の親要素で囲む必要があることが説明されています。また、コンポーネントの名前は大文字で始め、HTMLタグは小文字で書く必要があります。

:::warning エラーが出たら、まずJSXの書き方を確認する
初心者がつまずきやすいのは、タグの閉じ忘れや、複数の要素を親要素で囲んでいないことです。CSSのクラスを指定するときは、HTMLの class ではなく className を使う点も覚えておきましょう。
:::

## 環境づくりはどうする？

公式ドキュメントのインストールのページでは、Reactを試すために何かをインストールする必要はなく、ドキュメント内のサンドボックスを直接編集できると案内されています。ドキュメントの外にも、CodeSandboxやStackBlitz、CodePenといったReactに対応したオンラインのサンドボックスがあると紹介されています。

自分のパソコンで本格的にアプリを作る段階になったら、公式ドキュメントでは、新しいReactアプリを立ち上げる場合は**推奨されるフレームワークを使ってアプリを作成する**よう案内されています。Reactを基本から学びたい場合は、ゼロからReactアプリを構築する方法も紹介されています。

なお、同ページでは、以前よく使われていた**Create React Appは非推奨**になったと明記されています。古い本や記事の手順を見るときは、この点に注意しましょう。

## 作ってみたいアプリの例

検索では「React 初心者 アプリ」「React 初心者 向け」も調べられています。最初に作るアプリは、学んだ仕組みを一つずつ試せる小さなものがおすすめです。

:::point 初心者が作りやすいアプリの例
- やることリスト（タスク管理）：リストの表示、追加、削除で、stateとリストのレンダーを練習できる
- カウンター：ボタンで数字が増えるだけのアプリで、イベントとstateの基本を確かめられる
- 簡単なメモ帳：入力欄の扱いや、条件付きレンダーを練習できる
:::

**完成度より「自分で考えて書いた」ことを大切にしましょう**。チュートリアルの写経だけでは、自分で設計する力はなかなかつきません。小さくても、自分で決めた機能を形にすることが次の学習につながります。作ったアプリをポートフォリオにまとめる方法は {{link:engineer-portfolio-tsukurikata|エンジニアのポートフォリオの作り方}} で整理しています。

## よくある質問

### Reactは何から勉強すればいい？

JavaScriptの基礎（関数、配列、オブジェクトなど）を確認したうえで、React公式ドキュメント（日本語版）のクイックスタートとチュートリアルから始めるのがおすすめです。そのあと「UIの記述」「インタラクティビティの追加」へと進みましょう。

### Reactの勉強はJavaScriptを先に学ぶべき？

Reactのコンポーネントは、マークアップを返すJavaScript関数として書かれます。全部を完璧にする必要はありませんが、関数や配列の扱いに慣れておくと、Reactの理解が楽になります。

### Reactは無料で勉強できる？

React公式ドキュメントには日本語版があり、無料で読めます。ほとんどのページにブラウザ上で試せるサンドボックスがあり、インストールなしで試せると案内されています。

### React初心者におすすめのアプリは？

やることリスト（タスク管理）やカウンターなど、小さなアプリがおすすめです。やることリスト（タスク管理）では、リストの表示や追加・削除を通じて、stateとリストのレンダーの考え方を練習できます。

### Create React Appで始めてもいい？

React公式ドキュメントでは、Create React Appは非推奨になったと明記されています。新しくアプリを作る場合は、公式ドキュメントで案内されている方法を確認しましょう。
