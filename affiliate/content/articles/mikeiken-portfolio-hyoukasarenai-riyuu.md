未経験のポートフォリオが評価されない主な理由は、**「教材の作品をほぼそのまま載せている」「何を考えて作ったのかが伝わらない」「応募先の仕事と結びついていない」**の3つに集約されることが多いです。作品の完成度そのものより、「この人は入社後に自分で考えて伸びていけるか」が伝わるかどうかが分かれ目になります。

つまり、ポートフォリオは作品を並べる場所ではなく、自分の考え方と学ぶ力を伝える資料です。見せ方や説明を見直すだけで、同じ作品でも受け取られ方が変わることがあります。

この記事では、未経験者のポートフォリオが評価されにくい理由を7つに整理し、見直しの手順とREADMEの書き方を紹介します。

## 採用担当者はポートフォリオで何を見ているか

未経験者の採用では、実務経験がないぶん、ポートフォリオが「入社後にどれだけ伸びそうか」を判断する材料になります。見られやすいのは、次のような点です。

- **自分で考えて作ったか**：何のために、誰のために作ったのかを説明できるか
- **つまずきをどう乗り越えたか**：エラーや設計の悩みにどう向き合ったか
- **基礎を理解しているか**：使った技術を、なぜ選んだのか説明できるか
- **学び続けられるか**：作った後も改善を続けているか

ハローワークインターネットサービスの応募書類のガイドでは、アピールポイントには自分の性格や行動特性が現れたエピソードを示すと効果的だとされています。ポートフォリオも同じで、作品そのものに加えて、作る過程のエピソードが伝わると評価されやすくなります。

## 未経験のポートフォリオが評価されない7つの理由

| 理由 | よくある状態 | 見直しの方向 |
|---|---|---|
| ① 教材の作品そのまま | 学習教材で作ったアプリをほぼ同じ形で載せている | 機能を追加する、テーマを変えるなど、自分で考えた部分を加える |
| ② 目的が伝わらない | 何のためのアプリか説明がない | 誰のどんな課題を解決するのかを最初に書く |
| ③ 説明（README）がない | ソースコードだけが置いてある | 作った理由、機能、使った技術、工夫、苦労を書く |
| ④ 動かせない・見られない | 公開されておらず、手元でしか動かない | 公開して見られる状態にするか、画面の画像や動画を用意する |
| ⑤ 応募先とずれている | 応募する仕事と関係のない技術ばかり | 応募先で使う技術や業務に近い作品を前に出す |
| ⑥ 量に頼っている | 小さな作品をたくさん並べている | 説明できる作品を厳選し、代表作を決める |
| ⑦ 更新が止まっている | 作ったきりで改善の跡がない | 改善した点や今後の予定を記録する |

### ① 教材の作品をそのまま載せている

学習教材で作った作品は、学んだ証拠にはなりますが、同じ教材で学んだ人も似た作品を持っています。そのため、それだけでは「自分で考える力」を示しにくくなります。教材の作品を土台にする場合でも、テーマを自分の関心に合わせて変える、機能を一つ追加するなど、自分で考えた部分を加えましょう。

### ② 目的が伝わらない

「タスク管理アプリ」「ブログ」のように、何を作ったかだけが書かれていて、なぜ作ったのかが分からないケースです。前職で感じた不便や、身近な人の困りごとなど、作った動機を一言で添えるだけでも、考えて作ったことが伝わりやすくなります。

### ③ 説明（README）がない

ソースコードだけを置いても、忙しい採用担当者がすべてを読み解くのは難しいものです。作品の説明は、次の章で紹介するREADMEにまとめましょう。

### ④ 動かせない・見られない

採用担当者が作品を確認しようとしたときに、公開されていなかったり、手元の環境でしか動かなかったりすると、中身を見てもらえないまま終わってしまうことがあります。作品を公開して誰でも見られる状態にするか、難しい場合は画面の画像や操作の様子が分かる動画を用意しておきましょう。応募前には、別の端末やブラウザから実際に開けるかを確認しておくと安心です。

### ⑤ 応募先とずれている

Web系の自社開発企業に応募するのに、応募先と関係のない技術の作品ばかりを並べていると、入社後の姿を想像してもらいにくくなります。応募する職種や求人票の仕事内容を確認し、関連が深い作品を代表作として前に出しましょう。

## 作品の説明（README）に書きたいこと

GitHubの公式ドキュメント「リポジトリの README ファイルについて」では、READMEはリポジトリへの訪問者が最初に目にすることが多いアイテムであり、通常、次のような情報が含まれると説明されています。

- このプロジェクトが行うこと
- このプロジェクトが有益な理由
- このプロジェクトの使い始め方
- このプロジェクトに関するヘルプをどこで得るか
- このプロジェクトのメンテナンス者とコントリビューター

転職用のポートフォリオでは、これに加えて「なぜ作ったのか」「工夫したこと」「苦労したことと、その解決方法」を書くと、考え方や学ぶ姿勢が伝わりやすくなります。

:::steps 転職用READMEの構成例
1. **概要**：何を作ったのかを一言で書き、画面の画像を載せる。
2. **作った理由**：誰のどんな課題を解決したいと考えたのかを書く。
3. **主な機能**：できることを箇条書きでまとめる。
4. **使った技術と選んだ理由**：言語やフレームワーク、なぜそれを選んだかを書く。
5. **工夫した点・苦労した点**：つまずいたことと、どう解決したかを具体的に書く。
6. **今後の改善予定**：追加したい機能や、改善したい点を書く。
:::

なお、同じドキュメントによると、自分のユーザー名と同じ名前の公開リポジトリのルートにREADMEファイルを追加すると、そのREADMEが自分のプロフィールページに自動的に表示されます。プロフィールのREADMEに自己紹介と代表作へのリンクをまとめておくと、採用担当者が全体を把握しやすくなります。

## 未経験のポートフォリオはどのレベルが必要か

「どのくらいのレベルの作品なら評価されるのか」と悩む人も多いでしょう。決まった基準はありませんが、大切なのは高度な技術を使うことよりも、**基礎を理解したうえで、自分で考えて作り切ったことを説明できるか**です。

基礎の理解を確かめたい場合は、IPAの基本情報技術者試験の出題範囲を学習の目安にする方法もあります。IPAはこの試験を「ITエンジニアの登竜門」とし、対象者像として、ITを活用したサービスや製品、システム、ソフトウェアを作る人材に必要な基本的知識・技能を持つ人を挙げています。資格は必須ではありませんが、ポートフォリオと合わせて基礎知識を示す材料になります。

:::warning ポートフォリオ作りで避けたいこと
- 他人のコードやデザインを、出典を示さずに自分の作品として載せる
- パスワードやAPIキーなどの秘密情報を、公開リポジトリに含める
- 実際には理解していない技術を、使いこなせるように書く
- 作品の数を増やすことを優先し、説明が手薄になる
:::

## ポートフォリオを見直す手順

評価されないと感じたら、次の順番で見直してみましょう。

1. 応募したい職種と求人票を読み、求められている技術と仕事内容を書き出す
2. 手持ちの作品の中から、応募先に最も近い作品を代表作に決める
3. 代表作のREADMEに、作った理由、工夫、苦労と解決方法を書き足す
4. 作品を公開し、誰でも見られる状態か確認する
5. 第三者に見てもらい、分かりにくい点を直す

最後の「第三者に見てもらう」は特に効果的です。自分では分かっているつもりの説明も、初めて見る人には伝わらないことがあります。IT業界に詳しい転職エージェントでは、応募書類の添削とあわせて、ポートフォリオの見せ方について意見をもらえる場合があります。

## よくある質問

### 未経験のエンジニア転職でポートフォリオなしでも応募できますか？

応募自体はできますが、実務経験がない場合、学習の成果を示す材料が少なくなります。ポートフォリオがあると、学んだことや考え方を具体的に伝えやすくなるため、小さくても説明できる作品を一つ用意しておくのがおすすめです。

### ポートフォリオの例として、どんな作品が評価されやすいですか？

決まった正解はありませんが、自分や身近な人の課題を解決するために作った作品は、作った理由を説明しやすく、考え方が伝わりやすい傾向があります。前職の業務を効率化するツールなど、経験と結びつく作品も説明しやすいでしょう。

### Webデザイナー志望の未経験ポートフォリオでも同じ考え方でいいですか？

基本の考え方は同じです。デザインの場合も、見た目の美しさに加えて、誰に向けて、何を伝えるために、なぜその配色や構成にしたのかを説明できることが大切です。

### ポートフォリオは何個くらい作ればいいですか？

数よりも、説明できる作品を厳選することが大切です。代表作を一つ決めて説明を充実させ、そのほかの作品は補足として見せる形にすると、見る人に伝わりやすくなります。
