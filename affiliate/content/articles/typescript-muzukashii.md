JavaScriptでなんとか動くものを作れるようになり、次はTypeScriptだと思って始めてみた。ところが、画面が赤い波線だらけになり、型のエラーの意味が分からないまま、何時間も同じところで止まっている。そんな場面を想定して書きました。動いていたはずのコードに次々とエラーが出ると、自分に向いていないのではと不安になるものです。

TypeScriptが難しいと感じやすいのは、**JavaScriptの知識に加えて「型」という新しい考え方を同時に身につける必要がある**からです。ただし、TypeScriptの公式ドキュメントによると、**TypeScriptはJavaScriptの機能をすべて持ち、その上に型システムを加えたもの**で、**動いているJavaScriptのコードはそのままTypeScriptのコードでもある**とされています。

つまり、TypeScriptは「まったく新しい言語」ではなく、**JavaScriptに型のチェックを足したもの**です。この関係を理解し、型を少しずつ足していく学び方をすれば、難しさはぐっと小さくなります。

## TypeScriptが難しいと感じやすい理由

| 難しさの種類 | 内容 |
| --- | --- |
| 型の考え方 | 変数や関数がどんな値を扱うのかを、意識して書く必要がある |
| エラーの読み方 | 型のエラーメッセージが長く、何が問題か読み取りにくいことがある |
| 設定ファイル | tsconfig.jsonなどの設定項目が多く、最初は戸惑いやすい |
| JavaScriptの理解 | JavaScriptの動きが分かっていないと、型の意味もつかみにくい |
| 高度な型 | ジェネリクスなど、慣れるまで時間がかかる書き方がある |

検索では「TypeScript 型 難しい」も調べられています。結局のところ、**難しさの中心は「型」**です。ただ、型を最初から完璧に書く必要はなく、**よく使う基本の型から少しずつ慣れていけば十分**です。

## 公式ドキュメントが示すTypeScriptの目的

TypeScriptの公式ハンドブックでは、プログラマーが書くエラーの中で最も多い種類は**「型のエラー」**、つまり、ある種類の値が期待されている場所に別の種類の値が使われてしまうことだと説明されています。そして、TypeScriptの目的は、**JavaScriptのプログラムの静的な型チェッカーになること**、つまり、コードを実行する前に型が正しいかを確かめる道具になることだとされています。

また、公式ドキュメント「TypeScript for JavaScript Programmers」では、**TypeScriptの主な利点は、コードの思わぬ動きを指摘し、バグの可能性を下げられること**だと説明されています。

**赤い波線のエラーは「失敗」ではなく、「実行する前にバグを見つけてくれている」サイン**です。そう考えると、エラーとの付き合い方も少し楽になります。

## 型推論があるので、すべてに型を書く必要はない

同じ公式ドキュメントでは、TypeScriptは多くの場合に**自動で型を判断（型推論）**すると説明されています。たとえば、変数に文字列を代入すると、その変数は文字列型として扱われます。

:::point 型推論を活かすコツ
- 変数を作るときに値を入れれば、型は自動で判断されることが多い
- 型を明示的に書くのは、関数の引数や、オブジェクトの形を決めたいときから始める
- エディタで変数にカーソルを合わせて、判断された型を確かめる習慣をつける
:::

公式ドキュメントでは、Visual Studio CodeのエディタはTypeScriptを裏側で使い、JavaScriptの入力補完などを行っているとも説明されています。**エディタの表示を見ながら型を確かめる**のは、型に慣れるいちばんの近道です。

## つまずきやすいポイントと乗り越え方

### JavaScriptの基礎があいまいなまま始めている

公式ハンドブックでは、JavaScriptの経験がなくTypeScriptを最初の言語にしようとしている場合は、**先にMicrosoft LearnのJavaScriptチュートリアルや、MozillaのWeb DocsでJavaScriptを学ぶ**ことを勧めています。TypeScriptでつまずいたときは、原因がJavaScriptの理解にないかも振り返ってみましょう。

JavaScriptでつまずきやすいところは {{link:javascript-dokugaku-muzukashii|JavaScriptの独学が難しいと感じる理由は？}} で整理しています。

### エラーメッセージが読めない

型のエラーメッセージは長くなりがちですが、**「何の型を期待していたのに、何の型が来たのか」**が書かれていることがほとんどです。最初の一文と、期待された型・実際の型の部分に注目して読みましょう。

### 最初から高度な型を使おうとしている

ジェネリクスや複雑な型の組み合わせは、最初から使いこなす必要はありません。**まずは基本の型（文字列・数値・真偽値・配列・オブジェクト）とinterfaceを使えるようになる**ことを目標にしましょう。

:::warning 型をごまかす書き方に頼りすぎない
エラーを消すために、どんな型でも受け入れる書き方を多用すると、TypeScriptを使う意味が薄れてしまいます。エラーが出たら、まず「なぜその型が合わないのか」を考える習慣をつけましょう。
:::

## 挫折しにくい学ぶ順番

:::steps TypeScriptの学び方
1. **JavaScriptの基礎を確認する**：変数、関数、配列、オブジェクトの扱いに慣れておきます。
2. **型推論を体験する**：エディタで変数にカーソルを合わせ、自動で判断された型を確かめます。
3. **基本の型を書く**：関数の引数や戻り値に、文字列・数値などの基本の型を書いてみます。
4. **interfaceでオブジェクトの形を決める**：よく使うデータの形を、interfaceで表してみます。
5. **小さなアプリをTypeScriptで書き直す**：JavaScriptで作ったものを、少しずつTypeScriptに置き換えます。
:::

**JavaScriptで作ったことのある小さなアプリを、TypeScriptで書き直してみる**のがおすすめです。動きを知っているコードに型を足していくので、型の意味に集中して学べます。ReactでTypeScriptを使う予定がある人は、{{link:react-benkyou-houhou|Reactの勉強方法}} も参考にしてください。

## よくある質問

### TypeScriptはなぜ難しいと言われる？

JavaScriptの知識に加えて、「型」という新しい考え方を同時に身につける必要があるためです。エラーメッセージが長いことや、設定ファイルの項目が多いことも、最初に難しく感じる理由になります。

### TypeScriptはJavaScriptを知らなくても学べる？

公式ハンドブックでは、JavaScriptの経験がなくTypeScriptを最初の言語にしようとしている場合は、先にMicrosoft LearnのJavaScriptチュートリアルや、MozillaのWeb DocsでJavaScriptを学ぶことが勧められています。

### TypeScriptはすべての変数に型を書く必要がある？

公式ドキュメントによると、TypeScriptは多くの場合に自動で型を判断（型推論）します。最初は、関数の引数やオブジェクトの形など、必要なところから型を書き始めれば十分です。

### TypeScriptの型が難しいときはどうすればいい？

まずは文字列・数値・真偽値・配列・オブジェクトなどの基本の型と、interfaceを使えるようになることを目標にしましょう。エディタで変数にカーソルを合わせて、判断された型を確かめる習慣も役立ちます。
