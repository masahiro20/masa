プログラミングを学ぼうと思ったら、エラーメッセージも公式資料も英語ばかり。それなら英語も一緒に勉強したほうがいいのでは、でも二つも同時にできるだろうか、と迷っている。そんな場面を想定して書きました。欲張りすぎではないかと不安になるのは、自然なことです。

英語とプログラミングは、**目的によっては同時に学ぶ価値があります**。プログラミングでは、エラーメッセージや公式ドキュメント、海外の情報など、英語に触れる場面が多いからです。ただし、**両方を一から同時に始めると、学習時間が足りなくなりやすい**のも現実です。

おすすめは、**プログラミングを主にしながら、その中で出会う英語を少しずつ身につける**進め方です。英語環境で働きたいなど、英語そのものが目的に含まれる場合は、両方をまとめて学べる環境を選ぶのも一つの方法です。

## プログラミングで英語が必要になる場面

検索では「プログラミング 英語 必要」「プログラミング 英語 できない」もよく調べられています。プログラミングで英語に触れる主な場面は、次のとおりです。

| 場面 | 例 |
| --- | --- |
| コードを書く | 変数名や関数名、予約語など、英単語をもとにした言葉を使う |
| エラーを読む | 多くのエラーメッセージは英語で表示される |
| 公式ドキュメントを読む | 日本語訳がある場合も、原文は英語であることが多い |
| 情報を調べる | 最新の情報や解決策が英語で書かれていることがある |
| 開発に参加する | 不具合の報告や議論を英語で行うことがある |

たとえば、Pythonの公式ドキュメント（日本語版）の「バグへの対処」のページでは、Pythonの不具合を報告するフォームの「Title」欄に、問題のとても短い説明を英語で入力するよう、訳注つきで案内されています。また、ドキュメントの翻訳については、翻訳用のリポジトリが別に用意されていることも説明されています。

MDN Web Docsの「ウェブ開発の学習」のページにも、コミュニティの尽力で英語から翻訳されたものであることが表示され、英語版へのリンクが用意されています。**日本語の情報も充実していますが、原文は英語**という場面が多いことが分かります。

## 同時に学ぶメリットと注意点

:::merit 同時に学ぶメリット
- エラーメッセージや公式ドキュメントを読むときの抵抗が小さくなる
- 英語の情報にもアクセスでき、調べられる範囲が広がる
- 英語を使う職場や、海外とやり取りする仕事を目指しやすくなる
:::

:::demerit 同時に学ぶときの注意点
- 学ぶことが二倍になり、どちらも中途半端になりやすい
- 学習時間の確保が難しく、挫折につながることがある
- 目的がはっきりしないと、優先順位をつけにくい
:::

**大切なのは、「英語が必要だから」ではなく「何のために英語が必要か」を考えること**です。エラーを読めるようになりたいのか、英語で会議をしたいのかで、必要な英語の量はまったく違います。

:::warning 「英語ができないとプログラミングは無理」ではない
プログラミングに必要な英語の多くは、決まった単語や表現の繰り返しです。最初から英語が得意である必要はありません。分からない英語は、翻訳ツールや辞書で調べながら進めれば大丈夫です。
:::

## どちらを優先するかの判断基準

目指す働き方によって、優先順位は変わります。

| 目指すこと | 優先の考え方 |
| --- | --- |
| 国内の企業でエンジニアとして働きたい | プログラミングを優先し、英語は読む力から少しずつ |
| 外資系企業や英語を使う職場で働きたい | 両方を計画的に学ぶ。英語での面接やコミュニケーションも視野に |
| 海外の情報を使って学習効率を上げたい | プログラミングを主にし、技術文書を読む英語を中心に |
| 副業で海外の案件も受けたい | プログラミングで実績を作りつつ、やり取りに必要な英語を学ぶ |

**どの場合も、プログラミングで「動くものを作れる」状態を先に目指す**のが、遠回りしにくい進め方です。英語は、プログラミングの学習で出てきた単語や表現から覚えていくと、実際に使う場面と結びついて身につきやすくなります。

## 無理なく両立する進め方

:::steps 両立の進め方
1. **目的を決める**：英語をどこまで使えるようになりたいかを、働き方と結びつけて決めます。
2. **プログラミングの基礎を始める**：まずは日本語の教材で、プログラミングの基礎を学びます。
3. **エラーメッセージを英語のまま読む**：エラーが出たら、まず英文を読んでから翻訳ツールで確かめます。
4. **よく出る単語をメモする**：コードやエラーに何度も出てくる単語を、自分用の単語帳にまとめます。
5. **英語の公式ドキュメントに触れる**：基礎に慣れたら、日本語訳と英語版を見比べて読んでみます。
:::

エラーメッセージを読む習慣は、プログラミングそのものの理解にもつながります。Javaのように英語のエラーでつまずきやすい言語の例は {{link:java-dokugaku-muzukashii|Javaの独学が難しいと言われる理由は？}} でも紹介しています。

プログラミングを何から始めるか迷っている人は {{link:programming-dokugaku-nanikara|プログラミング独学は何から始める？}}、Web制作の基礎から学びたい人は {{link:html-css-javascript-dokugaku|HTML・CSS・JavaScriptを独学する順番は？}} を参考にしてください。

## プログラミングでよく出会う英語の例

検索では「プログラミング 英語 一覧」「プログラミング 英語 命名」も調べられています。プログラミングで使う英語は、日常会話の英語とは少し性質が違います。決まった単語が繰り返し出てくるので、慣れてしまえば読める部分が増えていきます。

### コードの中の単語

多くのプログラミング言語では、if（もし）、else（そうでなければ）、for（繰り返し）、return（戻す）のように、英単語をもとにした言葉で処理を書きます。意味を知っておくと、コードを読むときに処理の流れをイメージしやすくなります。

### 名前の付け方

変数や関数には、自分で名前を付けます。user_name や get_total_price のように、何を表すかが分かる英語で名前を付けることが一般的です。**名前を見ただけで役割が伝わるようにする**ことは、自分が後で読み返すときにも、ほかの人と一緒に開発するときにも役立ちます。

### エラーメッセージの言葉

エラーメッセージには、error（エラー）、not found（見つからない）、invalid（無効な）、undefined（定義されていない）といった言葉がよく出てきます。全文を訳せなくても、こうした単語から「何が起きたか」の見当をつけられるようになると、エラーの解決が早くなります。

## 社会人が両立するときの時間の使い方

働きながら英語とプログラミングの両方を学ぶ場合は、時間の使い方を工夫しないと、どちらも続かなくなりがちです。ここで迷う方は多いです。

**まとまった時間はプログラミングにあて、すき間時間で英語に触れる**、という分け方が取り入れやすいでしょう。通勤中に学習中に出てきた単語を見直す、休憩中に英語の技術記事のタイトルだけ読んでみる、といった小さな積み重ねでも、少しずつ英語への抵抗は減っていきます。

## 迷ったときの次の一歩

迷ったら、まずはプログラミングの入門教材で短いコードを書き、出てきたエラーメッセージを英語のまま読んでみてください。思ったより読める部分があると気づければ、英語との距離も少し縮まります。

スクールを検討する場合も、カリキュラムや受講ペースが自分に合わなければ見送って構いません。目的に合った学び方を、無理のないペースで選んでいきましょう。

## よくある質問

### プログラミングに英語は必要？

コードの単語、エラーメッセージ、公式ドキュメントなど、英語に触れる場面は多くあります。ただし、最初から英語が得意である必要はありません。翻訳ツールや辞書を使いながら、必要な単語や表現から少しずつ覚えていけば大丈夫です。

### 英語とプログラミングは同時に学ぶべき？

目的によります。英語を使う職場を目指すなら同時に学ぶ価値がありますが、そうでなければプログラミングを主にし、その中で出会う英語を覚えていく進め方がおすすめです。

### 英語ができなくてもプログラミングは学べる？

学べます。日本語の教材や情報も多くあります。エラーメッセージを英語のまま読む習慣をつけると、プログラミングの理解と英語の両方に役立ちます。

### 英語とプログラミングを学べるスクールの選び方は？

英語とプログラミングのどちらに比重を置いたカリキュラムか、授業の言語、受講ペース、受講後の進路などを確認しましょう。自分の目的と学習時間に合うかを、無料の説明やカウンセリングで確かめると安心です。
