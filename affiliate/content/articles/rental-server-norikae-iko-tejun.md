レンタルサーバーの乗り換えは、「バックアップ → 新サーバー契約 → データ移行 → 動作確認 → ネームサーバー変更 → 旧サーバー解約」の順で進めるのが基本です。**旧サーバーを解約するのは、新サーバーでの表示とメールの動作を確認し終えてから**にしましょう。

WordPressサイトであれば、移行先のサーバー会社が用意している「簡単移行」機能を使うと、データのコピーやURLの書き換えを自動で行えることが多く、手作業より失敗のリスクを減らせます。

ただし、ネームサーバーの切り替えには反映までのタイムラグがあり、メールやSSLなどWordPress以外の設定も移す必要があります。この記事では、乗り換えの全体の流れと、つまずきやすいポイントを順番に整理します。

- レンタルサーバー乗り換えの全体の流れと、作業の正しい順番
- WordPressのデータを移す3つの方法と、それぞれの向き・不向き

- 旧サーバーを解約する前に確認したいチェックリスト
:::

## レンタルサーバーを乗り換える主な理由

乗り換えを検討するきっかけには、次のようなものがあります。

- 表示速度が遅い、アクセスが増えて負荷に耐えられなくなった
- 更新料金が上がった、またはより条件の良いプランに移りたい
- 推奨されるPHPのバージョンなど、新しい環境に対応したい
- 管理画面やサポートが使いにくい

一方で、乗り換えには作業時間と一定のリスクがかかります。現在のサーバーでプラン変更やPHPのバージョン変更で解決できる問題なら、乗り換えずに済む場合もあります。まず「何を改善したいのか」を整理し、乗り換え先でそれが本当に解決するのかを確認してから進めましょう。

## 乗り換えの全体の流れ

作業の順番を間違えると、サイトが表示されない期間ができたり、データを失ったりする原因になります。全体像は次のとおりです。

:::steps レンタルサーバー乗り換えの6ステップ
1. **現サーバーのバックアップを取る**：WordPressのファイルとデータベース、メールのデータを保存する。
2. **新しいサーバーを契約する**：旧サーバーはまだ解約しない。
3. **新サーバーにドメインを追加し、データを移す**：簡単移行機能、プラグイン、手動のいずれかで移行する。
4. **ネームサーバーを切り替える前に動作確認する**：hostsファイルを使って新サーバー上の表示を確認する。
5. **ネームサーバーを変更する**：ドメインの管理画面で、新サーバーのネームサーバーに切り替える。
6. **一定期間並行運用してから旧サーバーを解約する**：表示・メール・SSLが新サーバーで動くことを確認する。
:::

ポイントは、**新旧両方のサーバーが動いている期間をつくる**ことです。この期間があることで、切り替え中にアクセスした人も、どちらかのサーバーでサイトを見られる状態を保てます。

## ステップ1・2：バックアップと新サーバーの契約

### バックアップは移行方法に関係なく取る

WordPress.org日本語版の「WordPressの移行」では、サーバー間で移動するときの最初の手順として、ファイル・画像・プラグイン・データベースのバックアップが挙げられています。簡単移行機能を使う場合でも、万一に備えて自分でバックアップを取っておくと安心です。

あわせて、独自ドメインのメールアドレスを使っている場合は、メールのデータやアカウントの設定内容も控えておきましょう。メールはWordPressとは別にサーバー上で管理されているため、サイトを移しただけでは移行されません。

### 新サーバーの選び方

乗り換え先を選ぶときは、改善したい点が解決するかに加えて、WordPressの移行機能の有無を確認しておくと作業が楽になります。サーバー選びの基本的な観点は、{{link:wordpress-blog-start-server-domain-steps|WordPressブログの始め方}}の「レンタルサーバー比較時のチェックリスト」も参考になります。

特に次の点は、申し込み前に確認しておきましょう。

- 改善したい点（速度・容量・料金など）が解決できるプランか
- WordPressの簡単移行機能があるか、利用条件に自分のサイトが当てはまるか
- 無料SSLに対応しているか
- メールアカウントの数や容量が足りるか
- 旧サーバーの契約期間の残りと、新サーバーの課金開始のタイミング

## ステップ3：WordPressのデータを移す3つの方法

WordPressのデータを移す方法は、大きく3つあります。

| 方法 | 特徴 | 向いている人 |
|---|---|---|
| サーバー会社の簡単移行機能 | 移行元の情報を入力すると、データのコピーを自動で行う | 初めて移行する人、標準的な構成のサイト |
| 移行用プラグイン | WordPress上でデータをまとめて書き出し・読み込みする | 移行先に簡単移行機能がない場合 |
| 手動（FTPとデータベースの移行） | ファイルとデータベースを自分でコピーし、設定を書き換える | サーバーやデータベースの操作に慣れている人 |

### 簡単移行機能の利用条件の例

簡単移行機能は便利ですが、どのサイトでも使えるわけではありません。たとえば2026年10月時点のエックスサーバーのマニュアル「WordPress簡単移行」では、利用条件として、WordPressのバージョンが4.2〜7.1であること、PHPのバージョンが7.2以上であること、データベース容量が2GB以下であることが挙げられています。

また、マルチサイト機能を使っている場合や、WordPress.comからの移行の場合などは利用できないと記載されています。移行後にWordPressのマイナーバージョンが最新版に更新されるといった注意事項もあるため、使う前に移行先のマニュアルを確認しましょう。

### ドメインやURLを変える場合は特に注意

ドメインやURLが変わらない場合、WordPress.orgの解説では、ファイルとデータベースをコピーするだけで移動できるとされています（データベースの接続情報が変わる場合は wp-config.php の修正が必要）。

一方、同時にドメインやURLを変える場合は注意が必要です。同じ解説によると、テーマやウィジェットはURLの長さを含む形（シリアライズデータ）で値を保存していることがあり、単純な検索・置換をするとデータが壊れる可能性があります。**サーバーの乗り換えとドメインの変更は、できれば同時に行わない**ほうが安全です。

:::warning データ移行で多い失敗
- バックアップを取らずに移行を始め、失敗したときに元に戻せない
- ドメイン変更と同時に移行し、URLの置換でデータが壊れる
- 移行元で使っていたプラグインのライセンスや設定を引き継げていない
- 独自ドメインのメールを移行し忘れ、切り替え後にメールが届かない
:::

## ステップ4・5：動作確認とネームサーバーの変更

### 切り替え前にhostsファイルで確認する

ネームサーバーを切り替える前に、新サーバー上でサイトが正しく表示されるかを確認しておくと安心です。エックスサーバーのマニュアルでも、パソコンのhostsファイルを編集することで、ネームサーバー変更前に動作確認ができると案内されています。

hostsファイルの編集は自分のパソコンだけに効く設定で、確認が終わったら元に戻すのを忘れないようにしましょう。表示崩れや画像の欠け、管理画面へのログイン、問い合わせフォームの送信などを一通り確認しておくと、切り替え後のトラブルを減らせます。

### ネームサーバー変更と「反映の遅れ」

動作確認ができたら、ドメインを管理しているサービスの画面で、ネームサーバーを新サーバーのものに変更します。エックスサーバーのマニュアルでは、ネームサーバーは移行作業の完了後に変更するよう注意書きがあります。

ネームサーバーを変更しても、すぐにすべての閲覧者が新サーバーを見るわけではありません。JPRSの用語辞典によると、DNSの情報にはTTL（Time To Live）という、キャッシュに保持してよい時間が秒単位で設定されています。たとえばTTLが3600なら、最大3600秒（1時間）キャッシュされる可能性があるという意味です。

そのため切り替え直後は、古い情報を参照している人には旧サーバーのサイトが表示されることがあります。JPRSのコラム「DNSサーバーの引っ越し」でも、キャッシュが新しい情報に置き換わるまで新旧のサーバーを並行運用し、その後に旧サーバーを停止する手順が示されています。

:::point 切り替え期間中の考え方
ネームサーバーを変更した直後は、新旧どちらのサーバーが表示されるかが閲覧者によって異なります。この期間に旧サーバー側で記事を更新したりコメントを受け付けたりすると、新サーバーに反映されません。切り替え期間中は記事の更新を控え、旧サーバーはすぐに解約しないのが基本です。
:::

### SSLの設定を確認する

新サーバー側でも独自ドメインのSSL（https化）を設定する必要があります。SSL証明書の発行タイミングはサーバー会社によって異なり、ネームサーバーの切り替え後でないと発行できない場合もあります。切り替え後に https でアクセスできるか、警告が出ないかを確認しましょう。

## ステップ6：旧サーバーを解約する前の確認

旧サーバーの解約は、新サーバーでの運用が安定してから行います。解約してしまうと、データを取り出せなくなる場合があるためです。

:::check 旧サーバー解約前のチェックリスト
- 新サーバーで、トップページ・記事・画像が正しく表示される
- https でアクセスでき、証明書の警告が出ない
- WordPressの管理画面にログインでき、記事の投稿・更新ができる
- 独自ドメインのメールが送受信できる
- 問い合わせフォームなどの送信が届く
- 旧サーバーのバックアップを手元に保存している
- 旧サーバーでドメインを取得している場合、ドメインの管理を別に移す必要がないか確認した
:::

最後の項目は見落としがちです。旧サーバー会社の特典でドメインを取得している場合、サーバーの解約と一緒にドメインの扱いが変わることがあります。その場合は、ドメインを別の管理サービスに移す（移管する）手続きを先に済ませておきましょう。

## 自分で乗り換えるか、代行を使うか

サーバー会社によっては、移行作業の代行サービス（有料の場合が多い）を用意しています。

:::merit 自分で乗り換えるメリット
- 費用を抑えられる
- 移行の流れを理解でき、今後のトラブル対応に役立つ
- 作業のタイミングを自分で決められる
:::

:::demerit 自分で乗り換えるデメリット
- 作業時間がかかり、慣れないとつまずきやすい
- 構成が複雑なサイトでは、データ破損などのリスクがある
- トラブルが起きたときに自分で原因を調べる必要がある
:::

標準的な構成のブログで、移行先に簡単移行機能があるなら、自分で乗り換えられる可能性は十分にあります。ECサイトや会員サイトなど止められないサイト、マルチサイトなど特殊な構成のサイトは、代行や専門家への依頼も検討しましょう。

## よくある質問

### サーバーを乗り換えるとSEO（検索順位）に影響しますか？

ドメインとURLが変わらず、移行後もページが正しく表示されていれば、サーバーを変えたこと自体が大きな問題になるケースは多くないと考えられます。ただし、切り替え時にページが表示されない期間が長く続いたり、URLが変わったりすると影響が出る可能性があります。動作確認と並行運用を丁寧に行うことが大切です。

### ネームサーバーの変更はどれくらいで反映されますか？

DNSの情報はTTLで決められた時間だけキャッシュされるため、反映までの時間は設定や閲覧者の環境によって異なります。変更直後は新旧どちらのサーバーが表示されるか分からない期間があるため、旧サーバーは一定期間残しておきましょう。

### 旧サーバーはいつ解約すればいいですか？

ネームサーバーを切り替えたあと、新サーバーでサイトの表示・管理画面・メール・SSLがすべて問題なく動くことを確認してからです。解約前に、旧サーバーのバックアップを手元に保存しておくと安心です。

### メールアドレスもそのまま使えますか？

独自ドメインのメールアドレスは、新サーバーで同じアカウントを作成し直すことで引き続き使えるのが一般的です。ただし、メールのデータやアカウントは自動では移らないことが多いため、ネームサーバーを切り替える前に新サーバー側でアカウントを作成し、必要に応じて過去のメールも保存しておきましょう。
